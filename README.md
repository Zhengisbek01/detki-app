# Детки — мобильное приложение записи детей на секции

React Native + Expo (SDK 58), TypeScript, Expo Router. 4 роли: родитель, преподаватель, ребёнок, админ.
Данные — моковый API, оплата Kaspi — заглушка с готовым местом для интеграции.

## Запуск за 3 минуты (Expo Go)

1. Установите Node.js 20+ и на телефон приложение **Expo Go** (App Store / Google Play).
2. В папке проекта:
   ```bash
   npm install
   npx expo start
   ```
3. Отсканируйте QR-код камерой (iPhone) или из Expo Go (Android). Телефон и компьютер — в одной Wi-Fi сети
   (если нет — `npx expo start --tunnel`).
4. В браузере: `npx expo start --web`.

Вход: любой номер `+7 7xx xxx xx xx`, код — любые 4 цифры. На экране входа выбирается роль (демо).
Сменить роль потом: кнопка «Роль ⇄» в профиле / на главной ребёнка / в модерации.

Проверка типов: `npm run typecheck`.

## Как связаны роли (демо-сценарий)

1. **Родитель**: каталог → карточка → запись → оплата Kaspi → чек (5 экранов).
2. **Преподаватель**: «Сегодня» → посещаемость в один тап → стикеры группе.
   Алихан отмечен «пришёл» → у ребёнка +10 ⭐, растёт квест недели и командная цель.
3. **Ребёнок**: звёзды, уровень, серия с заморозкой, квесты, семейные призы, бейджи, стикеры от тренера, гардероб.
   «Я сделал!» → квест уходит на проверку родителю или тренеру.
   «Хочу приз» → запрос родителю.
4. **Родитель → Дети**: подтверждает квесты, выдаёт призы (звёзды списываются), создаёт свои призы.
5. **Админ**: модерация преподавателей и занятий, платежи (GMV, комиссия, НДС, эквайринг), возвраты и споры.

Состояние сохраняется на устройстве (AsyncStorage). Сброс: «Роль ⇄» → «Сбросить демо-данные».

## Структура

```
src/
  app/                    # экраны (Expo Router: файл = экран)
    index.tsx             # вход: язык, телефон, SMS, согласия на ПД, роль
    role.tsx              # смена роли (демо)
    parent/(tabs)/        # Поиск, Расписание, Дети, Профиль
    parent/class/[id].tsx, booking.tsx, pay.tsx, success.tsx
    teacher/(tabs)/       # Сегодня, Занятия, Финансы, Профиль
    teacher/attendance.tsx, praise.tsx, new-class.tsx
    child/(tabs)/         # Главная, Квесты, Призы, Награды
    child/team.tsx        # командная цель
    admin/(tabs)/         # Модерация, Платежи, Споры
  api/client.ts           # моковый API (заменить на fetch к бэкенду)
  api/mockData.ts         # тестовые данные из прототипа
  services/kaspi.ts       # ЗАГЛУШКА Kaspi — инструкция по интеграции внутри
  services/finance.ts     # комиссия 12%, НДС 16%, эквайринг 2%
  store/AppStore.tsx      # состояние и правила геймификации
  components/             # UI-кит (кнопки, карточки, теги…)
  theme.ts                # цвета (фиолетовый #6A4DFF и пастельные)
```

## Финансовые допущения (`src/services/finance.ts`)

| Параметр | Значение | Комментарий |
|---|---|---|
| Комиссия платформы | 12% | с каждой оплаты родителя |
| НДС РК | 16% (с 2026) | входит в комиссию: комиссия × 16/116 |
| Эквайринг Kaspi | ~2% | оценка, уточнить по договору |

Пример: GMV 12 400 000 ₸ → комиссия 1 488 000 ₸ → НДС 205 241 ₸ → эквайринг 248 000 ₸.

## Подключение реального бэкенда

1. Задайте `EXPO_PUBLIC_API_URL=https://api.ваш-домен.kz` в `.env`. Тогда `api/client.ts` пойдёт в сеть вместо моков.
2. Kaspi: в `services/kaspi.ts` поставьте `USE_MOCK = false`. Счёт создаёт **только бэкенд**
   (`POST /payments`), статус приходит вебхуком от Kaspi. Ключи в приложении не хранить.
3. SMS-вход: заменить `sendSmsCode` / `verifySmsCode` в `api/client.ts` (например, через Mobizon / SMSC.kz).
4. Фото занятий: `npx expo install expo-image-picker` и загрузка в хранилище.
5. Push-уведомления (стикеры, подтверждения): `expo-notifications`.

## Что в MVP не сделано (следующие шаги)

- Реальный бэкенд (рекомендация: NestJS/Supabase + PostgreSQL) и авторизация.
- Казахский и английский переводы всех экранов (сейчас переключается только экран входа).
- Отзывы, чат с преподавателем, карта.
- Веб-панель админа (в прототипе — мобильная версия ключевых экранов).
